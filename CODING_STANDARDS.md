# Coding standards

Rules for the code in COMPIES, on top of `GLOSSARY.md` and the ADRs. Rules a tool can check live in `eslint.config.mjs` and the tests; this file holds the judgement calls.

## Database

- A column a request filters or joins on gets its index in the same migration.
- An enum belongs to one glossary term. A concept with its own term gets its own enum, even when today's values match (games' Suitability is not the Event's Format).
- A migration that has run on staging is never edited; the fix is a new migration.
- Migrations run in the Vercel build while the previous deployment still serves (ADR 0007). A data migration keeps the app correct for the rows the old code writes after it ran.
- One lock order for every write: the Event rows first (in id order when there are several), then the users row. `deleteUser` and `changeEvent` follow it; locking the users row first deadlocks with a Host writing in their own Event.
- A write a User makes for themselves checks under a lock that their row is not deleted: `FOR KEY SHARE` with `deleted_at is null` after its Event lock and before its first write (`assertLiveUser`, `writerMembership` in `changeEvent`), or `liveUser(id)` in the `where` of an update of their own row, and 401 when no row is left.
- A change of an Event takes its instants from `EventChange.now` and never calls `useClock` in a handler; `changeEvent` settles due draws for every `lock: 'update'` change.

## Secrecy

What a feature keeps from some Users (a sealed Veto, a Hidden wheel before its stop), and what it starts showing to Members. Every 0.7 miss sat on a surface nobody had named.

- A change whose existence is secret commits with `changeEvent(…, { broadcast: false })` (ADR 0013). The `event.changed` that follows every other commit tells every Party that something happened.
- A value derived from secret rows is secret too, in every section of the read and in every message, Host-only ones included (a count of sealed casts, a Hidden wheel's slice order). `knownVetoRows` in `server/utils/vetoes.ts` is the one filter for what a viewer may know of the Vetoes; it asks `vetoesSealed` in `shared/draw-timeline.ts` whether a window still seals them.
- The Veto allowance is secret from every Member but the Host until the Event's first Session starts. Only the Event read's `poolsSection` masks it, through `settingsForViewer`; `test/integration/veto-allowance-secrecy.test.ts` searches the Player's reads, feed, room messages and every GET route for the number.
- An Archive entry whose Award ceremony has not been shown, or is still running, is closed and carries no `winners` and no `rank` key at all: `archiveEntry` leaves them out, the card derives no result of its own, and `test/integration/archive.test.ts` pins the closed keys.
- A feature that shows Members something they didn't see before (a player, a picture, a thumbnail, an image route) is checked against every section of the Datenschutzerklärung that says who sees what; the user approves the new text (§ Copy).
- A read, feed entry or message that names a drawn game goes through `drawGameKnown` (`shared/draw-timeline.ts`) or `stoppedDraws` (`server/utils/draw-timeline.ts`). A copy of the `stopAt <= now` comparison is wrong: `<` instead of `<=` leaks under a Hidden wheel, and the room carries no game data but `activity.added`. The one copy that stays is the Activity feed's `lte(activity.at, now)` for `INSTANT_ACTIVITY_TYPES` in `server/utils/activity.ts` (a `game_drawn` entry's `at` is its draw's `stopAt`); it is pinned against these two, so a new surface of the stop edge goes on the list in § One home per concern.

## Motion

- An animation takes the curve and the duration that `docs/design_handoff_compies/04-motion.md` names for its moment, as that entry's tokens (`--cp-ease-pop`, `--cp-dur-slow`).
- Its test asserts that easing and duration, as well as that something animated.
- Inside the GSAP timelines (ADR 0015, the Award ceremony's Pokal-Lauf) the eases are GSAP's named eases as `04-motion.md` writes them (`back.out(2.2)`), not `--cp-ease-*`, and their test reads the tween vars (`ease`, `duration()`) off the built timeline.
- An animation that lands on a result (the coin's face, the wheel's slice) also has a test that the landing shows that result.
- A motion's static fallback (reduced motion, a failed chunk, a skip) has a test for its geometry, as `test/unit/ceremony-run.test.ts` pins where Compibert stops.
- A `<Transition>` that mounts inside a pending Suspense runs no Transition hooks, so its enter does not play: mount it once its parent is mounted (as the Event page's header does for row 2).
- A padding change on an ancestor, in the render that resizes a block above the scroll anchor, drops Chrome's scroll anchoring, and the anchored block jumps; give the room a sibling element instead (as the stage group does for the Veto bar).

## Tests

- Test data has the shape production data has. A Member that a test renders (avatar, Game board, lists of people) comes with a picture, as every Discord and Twitch account does. Tests that draw a Member build it with `memberView()` in `test/nuxt/event-page.ts`.
- A list, a wheel or a count is tested at its edges: 0, 1 and 2 items, and the longest name allowed (`GAME_NAME_MAX`; the wheel cuts at its `LABEL_MAX`).
- A read section that grows over time (`setGame`, the Event read's sections) is asserted with `toMatchObject` or a fixture builder, not `toEqual` on the whole object.

## Copy

- UI copy uses the glossary's UI word. When the glossary retires a word, it goes into `RETIRED` in `test/support/retired-words.mjs` (`test/unit/copy.test.ts` reads it).
- Copy promises only what the app does today.
- A text says only what the screen does not already show: no kicker that repeats the page's title or place, no help line that restates its field, no pill for a state the screen already shows, no line that tells a Host what everyone will see anyway. A wink is welcome in empty states, errors, placeholders and Construction pages.
- Words for people are gender-neutral: a participle („Spielende“, „Teilnehmende“) or a neutral word („Leute“, „alle“), and the colon form („Freund:innen“) only where neither fits. A word that names a Party, not a person („Sieger“), stays.
- A form message (a validation) is red and shows only once its field was touched or a submit was tried; until then a disabled submit button says enough. Inputs that form one group (from and to, start, end and length, amount and source) share one message line under the group, as wide as the group.
- A new third party the browser or the server talks to goes into the Datenschutzerklärung; `test/unit/privacy-hosts.test.ts` names the host, and the user approves the text.
