The first button runs a fake save: the label is replaced but the width is held, and success stays silent (a check for 1.5 s, no toast).
Use for. Primary is the one next step on a screen (Rad drehen, Weiter, Session starten). Secondary is for parallel actions, ghost for dismissals and low-stakes actions, danger for irreversible ones.
Don't. Never put two primaries side by side. Don't use danger for things that can be undone (use ghost + an undo toast). Don't let a label wrap: shorten it ("Nochmal", not "Noch einmal versuchen").
Accessibility. Use a native <button>. Focus ring appears instantly (3 px, focus colour, 3 px offset). Disabled buttons use aria-disabled and stay focusable, with the reason in a tooltip. Loading sets aria-busy. Icon-only needs aria-label. Hit area is always ≥ 44 px.
Desktop and mobile. Desktop uses md, and sm only in dense tables. On mobile the primary action spans the full width and sticks to the bottom of the screen. Hover lift is off on touch; the press stays.

Hold to confirm

Used for veto, ban and pick. Hold for one second; let go early and nothing happens. A confirmed hold can't be undone.
Live: hold with mouse, touch, or Space

Use for. Only the three irreversible game actions: Veto, Ban, Pick. In a team, the first member to finish the hold wins. Everyone else's button switches to the team-locked state at once.
Don't. Don't use it for anything reversible or for settings. Don't shorten the hold below 800 ms or add a confirm dialog on top. Never hide the button behind the clip overlay (z-index veto 46 > clip 44).
Accessibility. Space or Enter held for 1 s works like a pointer hold; key repeat is ignored. aria-describedby explains the hold. Progress is announced at 50 % and on confirm. Profile setting: „Halten durch Doppelklick ersetzen“ (two presses within 1.5 s) for players who can't hold.
Desktop and mobile. Desktop: 56 px tall in the veto bar, never full width beyond 420 px. Mobile: full width, pinned to the bottom above the safe area. A long-press doesn't open the context menu, and there's a light haptic tap on confirm if the device supports it.

Native select: the system picker on mobile.
Use for. Session name, game name, YouTube link, start second, scores. Select for any list of 4+ fixed options (format, number of games); fewer options use radios.
Don't. No floating labels, no placeholder as the label, no validation while the user is still typing the first word. Check on pause (500 ms) or on blur. Don't build a custom dropdown when the native one works.

Desktop and mobile. Same 48 px height everywhere. Set inputmode (numeric for scores and seconds, url for YouTube). On mobile, the field scrolls above the keyboard and the stepper's bottom buttons stay visible.

Use for. Toggle: settings that apply immediately (Rad verdecken, Ton, Push). Checkbox: multi-select inside a form (pools, slot lists in the date poll). Radio: 2–4 exclusive options with a description. Slider: counts where the range matters (number of games, clip length).
Don't. Don't put toggles in forms with a Save button. Don't use a slider for exact values over 20 steps (use a number input with ± buttons). A disabled control always says why.
Accessibility. Roles: switch, checkbox (with mixed), radiogroup with roving tabindex + arrow keys, slider with valuetext („8 Spiele“). Whole rows are clickable, at least 44 px tall. The state shows as a shape (knob position, check, dot), never colour alone.
Desktop and mobile. Identical controls. On mobile the slider thumb grows to 32 px and the value bubble sits above the finger. Radios with long descriptions stack into full-width rows.

Toasts, notices, banners

Success is usually silent. Speak up for failures, for effects you can't see, and for things everyone needs to know right now.
Toasts appear at the top of the overlay stage above.
Banners: full width, under the header

Verbindung verloren. Deine Vetos sind sicher.Neu laden
Neuer Termin: Samstag, 25.10., 20:15 Uhr.ics laden
Inline notices: inside the content they're about
Nur du siehst das {{ n.txt }} {{ n.act }}
Use for. Toast: failures with a retry, and invisible effects (Link kopiert). Banner: room-wide state everyone must know (connection, rescheduled date). Inline notice: a condition tied to one area (uneven teams, pool warning for the host, locked team slots).
Don't. No „Gespeichert!“ toasts for things you can see changed. No coloured left stripe on notices. Game events (Glücksrad, Veto) go to the activity feed, not toasts. Never stack more than three toasts.
Accessibility. Toasts and info banners: role="status" (polite). Errors that need action: role="alert". Auto-dismiss only without an action, after at least 4 s, paused on hover and focus. Toasts with an action stay until dismissed.
Desktop and mobile. Toasts: top centre under the header on both, so they never collide with the host dock or the veto bar. Banners push the content down rather than covering it. On mobile, banner side text drops and the action becomes icon + short label.

Use for. Chat and Aktivität in the side panel; archive detail (Ergebnisse, Chat, Replay); profile sections.

Use for. Empty: chat, pools, library search, archive, date poll without slots. Skeleton: known layouts (cards, rows, leaderboard). Compibert thinking: unknown waits > 300 ms. Buttons show their own spinner for their own action.
