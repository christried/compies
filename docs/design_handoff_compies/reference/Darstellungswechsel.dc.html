3 · How it is drawn on top of the clip

  1. Origin and radius from the tapped element: centre of its getBoundingClientRect(); R = distance to the farthest viewport corner. Written to --vt-x --vt-y --vt-r on html (runtime values, not tokens).
  2. The clip: ::view-transition-new(root) animates clip-path: circle() from 0 to R. Both root pictures get animation:none; mix-blend-mode:normal, so the old one stays still and there is no default cross-fade.
  3. The edge is one real element, .theme-edge, fixed and full-viewport, inserted inside the update callback. It has its own view-transition-name: theme-edge: that takes it out of the root pictures and paints it as its own group above them. Its new-view is live, so its CSS animation plays through the transition.
  4. Inside: a disc centred on the origin, growing 0 → 2R with the clip’s duration and easing, so its border box is always exactly the clip circle. The edge parts are box-shadows on its children: outer shadows draw only outside the circle (on the old picture), inset only inside (on the new one).
  5. Sync: the edge’s animations are paused until transition.ready, then start in the same frame as the clip. Removed on transition.finished.
  6. Cost: one element, three boxes, no canvas, no image, no filter. During a View Transition the page under it is a snapshot anyway.

4 · The three places

  • Header (≥ 980 px): 40 px round button, left of Ton; icon = current look (sun / moon). Opens a 240 px menu, role="menu", three menuitemradio rows of 44 px with a check on the current one. Origin: the centre of the row.
  • Avatar menu: a row „Darstellung“ with three icon segments (40 × 36, aria-label Hell / Dunkel / System). On a phone it is the bottom sheet, the segments go full width with labels, 44 px tall. Origin: the centre of the segment.
  • Profil › Einstellungen: the existing SegmentedControl, with icons. Below 600 px it wraps under the label, full width, 44 px. Origin: the centre of the segment.
  • Menus close in the same update as the theme change (inside the transition callback); focus goes back to the trigger. The segmented control keeps focus on the tapped radio.

5 · Edge cases

  • No visible change, no circle. „System“ while the OS gives the same look, or tapping the current option: only the selection moves, instantly.
  • System changes later (OS switches at sunset while the app is open): cross-fade 140 ms. No tap, so no origin.
  • Tap during a transition: skipTransition() on the running one, then start the new one from the new tap.
  • Reduced motion (--cp-motion: reduced) with View Transitions: the default cross-fade at --cp-dur-fast, no edge element. No View Transitions: a 140 ms colour transition class on html, removed after.
  • SSR: cookie keeps first paint right; nothing animates on load.
  • No sound.

6 · Tokens used

  • Motion: --cp-dur-slower, --cp-ease-io (circle, disc), --cp-ease-linear (edge change), --cp-dur-fast (fallback).
  • Edge: {{ tokList }}
  • New tokens: none. --vt-x / --vt-y / --vt-r are per-transition runtime values set by JS, like the clip coordinates.
