### Should-fix

#### S1. The notes field tells the Host less than the app does (CODING_STANDARDS § Copy: „Copy promises only what the app does today“; ticket #217 story 19: free text can name people). Judgement

- `i18n/locales/de.json:866` `gameEdit.notesHelp`: „Einstellungen, Aufwärmen, Siegbedingung, Hausregeln. Alle Hosts können sie lesen.“

- Fix: put the rule and the handoff list in `docs/agents/` (a short section in `subagents.md` § Supervision, next to the three-implementer limit), name `scripts/context-usage.mjs` there, and cut the patch to: „**COMPIES:** before every new implementer (steps 4, 6 and 7) check the context limit (`docs/agents/subagents.md` § Supervision); at the limit, hand off instead.“ The README line for `implement-spec` stays as it is.

#### S3. „A Hidden wheel always has the Pool preview off“ is coded in five places (CODING_STANDARDS § One home per concern: „a rule both sides enforce … a pure function in `shared/`, called by the form and by the server parser“; baseline: Duplicated Code). Judgement

- Why: the rule has the same shape in the server parser, the stored-row reader, the merge, the draft and the switch. They agree today and the tests pin them, but the next change to the rule (0.7 adds a "drawn games" branch around it) has five places to find, and the draft/switch copies already differ in detail (the getter masks, `settingsOf` coerces, `hideWheel` also writes).
- Fix: one pure function in `shared/settings.ts`, for example `poolPreviewUnder(hiddenWheel: boolean, wanted: boolean): boolean`, called by `parseSettings`, `storedPoolPreview`, `settingsOf` and the switch's getter. `mergeSettings` can stay (it deals with what the change says, not with the value).

## Spec review: Release 0.6 „Notizen“ (v0.5.1...origin/feat/217-notizen, 34afda4)

### Result

### Should-fix

#### P1. „Rad verdecken“ turned off can switch Pool preview on: story 24 holds only when Pool preview was not touched in Host-Wahl in between
- `app/components/stepper/StepMode.vue:49-51` (`hideWheel`), `:42-47` (the `poolPreview` getter), `app/utils/event-draft.ts` `settingsOf`.
- Spec: #217 story 24 „As a Host who turns „Rad verdecken“ off again, I want „Pool vorher zeigen“ to stay off until I turn it on, so that nothing is revealed by surprise.“ and #225 „it stays off when „Rad verdecken“ is turned off“.
- Failure scenario (the stepper, and the settings editor of an Event that has not started): the Host picks Glücksrad and turns „Rad verdecken“ on (draft: `hiddenWheel: true`, `poolPreview: false`); switches to Host-Wahl, where the switch shows off and is enabled (the draft keeps `hiddenWheel: true`); turns „Pool vorher zeigen“ on there (draft `poolPreview: true`); switches back to Glücksrad. The getter masks it (`draft.poolPreview && !(wheel && hiddenWheel)`), so the switch shows off and disabled under „Rad verdecken“. The Host turns „Rad verdecken“ off: `hideWheel(false)` sets only `hiddenWheel: false`, the stale `poolPreview: true` surfaces, the switch flips to on, and the Event is saved with the pools visible to every Member. The Host never saw it on under the wheel. The test `stays off when „Rad verdecken“ is turned off again` covers only the direct path (hide, unhide), where `hideWheel(true)` has just set the draft value to false.
- Cost: pools shown to Members that the Host believed hidden; the secrecy of the Pool preview is the point of the Release. Narrow path, one-line fix.
- Fix: `hideWheel(false)` sets `poolPreview: false` too (`{ ...draft.value, hiddenWheel: false, poolPreview: false }`), so „turning it off leaves it off“ is true whatever the draft kept. Add a stepper case for the scenario above (hide, Host-Wahl, switch on, Glücksrad, unhide: the switch reads off).

#### P2. The notes field's help names only Hosts as readers, but Members read the notes too
- `i18n/locales/de.json:866` (`gameEdit.notesHelp`: „Einstellungen, Aufwärmen, Siegbedingung, Hausregeln. Alle Hosts können sie lesen.“), shown by `app/components/GameForm.vue:262`.
- Spec: #217 story 13 „As a Member of an Event whose pools I may see, I want a collapsible „Notizen“ under each game in „So wird gespielt““, story 19 (free text can name people, so the Datenschutzerklärung says who reads them), and `CODING_STANDARDS.md` § Copy „Copy promises only what the app does today.“
- What is wrong: the one place a Host writes the free text tells them that Hosts read it. Members of every Event whose pool holds the game and whose Pool preview is on read it as well, and since Pool preview is on by default that is the normal case. A Host who writes a remark about a named player, or a house rule they would not say aloud, reads this help and has no hint. The Datenschutzerklärung § 11 states the audience correctly; the form, where it matters, does not. The help string came from the brief, not from the user.
- Fix: name the audience, for example „… Alle Hosts können sie lesen, und die Mitglieder deiner Events, solange sie den Pool sehen.“ Update the pinning test in `test/nuxt/game-form.test.ts` if it asserts the string. Word it with the user, since the user approves privacy-relevant copy.

#### T1. „A Hidden wheel has no Pool preview“ is enforced in seven places, each with its own phrasing of the same rule (should-fix, medium; do as the first ticket of 0.7, before Glücksrad touches the Hidden wheel again)

The rule: under a Hidden wheel the Pool preview is off, and turning the Hidden wheel off leaves it off. It now sits in:
